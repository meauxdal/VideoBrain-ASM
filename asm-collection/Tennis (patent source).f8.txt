;       The coupler of the invention has been programmed, utilizing
;  the register implementation described [in the patent] to display
;  "Tennis" video game which is externally controlled by a user.
;  The following pages is program listing of the assembled language
;  for such game.  The microprocessor utilized is the previously
;  mentioned F8 microprocessor available from Mostek Corporation
;  and the Fairchild Camera and Instrument Corporation.    It was
;  programmed in accordance with the F-8 User's Guide and Guide to
;  Programming available in 1976 from Fairchild; and the 1975 F-8
;  Preliminary Data Book available from Mostek.  The memory
;  allocations (in hexadecimal) for the following are:
;
;       Cartridge "Tennis" Program      F800-FFAF
;       Display Composer                0800-08FF
;       Cartridge Segment Information   1200-1F9A
;  
;       Also, the designation UM1 is used to refer to the display
;  composer; and the designation UM 2 is used to refer collectively
;  to the system controller, the timer and the timing and
;  sync generator.
;
;  Special Notes about the Re-Typing of "Tennis" Assembly Code
;  -------------------------------------------------------
;
;  1) "Tennis" Source Code Version Tree:
;
;     There are four different distinct version trees for this
;     assembly code.  They are as follows: 
;
;        0.Xx - Source code in unifinished state; typing is not yet
;               complete.  Some preiminary versions were shared with
;               the "Channel_f_and_VideoBrain" YahooGroup.
;
;        1.x  - Source code is as close to original as possible, but
;               includes minimal additional comments and filler bytes.
;
;        2.x -  Source code is as close to original as possible, but
;               with MANY additional comments throughout, but no
;               other changes.
;
;        3.x -  Source code is BASED on original code, but "fixes"
;               and additions have been added.
;
;          Any user is free to user and modify the re-typed "Tennis"
;     "Tennis" sourse code, but please try to stay true to this
;     version tree for future users of this code.  
;
;  2) The original F8 assembler used to create the source in
;     the "Tennis" patent was not available.  This source code
;     has been created and assembled in the Windows XP environment
;     using the command line version of with DASM 2.20.11
;     for win32-x86.
;  
;  3) The purpose of this assembly source code for "Tennis" is to
;     match the binary output of the assembly listing in the patent.
;     Therefore, since the same F8 assembler used in 1977 is not
;     known or available, the source had to be changed, but the
;     spirit of the original assembly code has been kept as closely
;     as possible.  Although the source code itself looks different,
;     it creates a binary file that matches the "Tennis" patent's
;     assembly listing's binary output.  
;
;  4) Some lines in the assembly listing for the "Tennis" patent
;     are missing.  These have been marked with a comment that says:
;     "?? Missing line in assembly listing ($XXXX)," where XXXX is
;     the address of the missing line number.
;          A suggestion as to why some bytes are missing from the
;     assembly listing has been made.  On June 21, 2012, Sean
;     Riddle posted this to the "channel_f_and_videobrain" Yahoo
;     Group, "It looks like [the assembly lissing] was printed to a
;     serial printer and some bytes got lost. Probably a bit got
;     missed and so there were framing or parity errors and no
;     characters were printed until it got synchronized again."
;          An educated guess can be made to replace the data that is 
;     in some of the missing bytes, but in this version of the
;     assembly source code, the address of the missing bytes holds
;     different data depending on the address area in memory.  It
;     is setup like this:
;
;                 Area Type        ROM Address    ROM Address Contains
;            -------------------   -----------    --------------------
;        1.  "Data" Area           $1200-$12DC    $00 ("Empty Byte")
;        2.  "ROM Objects" Area    $12DD-$1714    $00 ("Empty Byte")
;        3.  "Main Program" Area   $1800-$1F9A    "NOP" Op Code
;   
;          Substituting either an "empty byte" or NOP allows the
;     final binary to run, although the missing data and/or opcodes
;     means that it won't run properly.
;     
;  5) In some cases a solution to a question about the source code
;     could not be reached.  In this case, a comment with '??' on
;     the line(s) in question is marked.  Lines such as this
;     typically do create the originally intended binary output but
;     often use a method that might not be preferred.  In some 
;     cases, the lines do NOT match the binary output.  In ALL
;     cases the '??' is meant to make the user of the re-typed
;     assembly code aware that something about those original
;     lines probably has not been carried through in the re-typed
;     "Tennis" source code. 
;      
;  6) Some usage of the DASM assembler "DC" (Declare Data)
;     directive will not work as listed in the original patent.
;     Some other method had to be used to setup multiple bytes of
;     data that didn't vary too much from the original source code.  
;          In other assemblers besides DASM, the assembly directive
;     "DS" usually means "Define Storage," but in DASM it means
;     "Define Space."  "DS" is the F8 op code "Decrement Scratchpad
;     Content," and therefore cannot be used as an assembler
;     directive.  However, Sean Riddle discovered that RES is a
;     synonym that can be used under DASM when using the "processor
;     f8" directive.  Here is an example of how it is used in this
;     source code:   
;
;       DC        4,$FF         ; Define 4 bytes of $FF in original
;                               ; source, but doesn't work properly
;                               ; with DASM
;           Use this instead:
;
;       RES.B     4,$FF         ; Define 4 bytes of $FF in DASM
; 
;          RES.B can also be used with labels, just as is done in
;     the original source code.  For example:
;
;     NH      EQU      60       ; NET HEIGHT (2 OBJECTS)
;
;       DC        NH,$C0        ; NH = 60, Define 60 bytes of $C0
;                               ; Doesn't work properly with DASM
;
;           Use this instead:
;
;       RES.B     NH,$C0        ; NH = 60, Define 60 bytes of $C0
;
;

;  assembly listing .  This may be because the lines that they were
;  created on are missing.  These ARE required for proper assembly.
;
